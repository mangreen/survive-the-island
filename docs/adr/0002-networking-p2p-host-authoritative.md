# ADR-0002：連線架構（房主權威 P2P）

- 狀態：方向已確認（開發計畫），實作在 M3–M5，連線層放在 peerhost
- 日期：2026-11-27
- 來源：擁有者的 king-of-tokyo ADR-0007

## 背景

2–6 人回合制，朋友間遊玩。伺服器成本要低，任何人都能當房主，也要能單人離線。

## 決定

- 房主權威的星狀 P2P。房主的瀏覽器跑規則與房間邏輯；伺服器只做靜態檔、房號登記、信令與中繼。
- 先走 WebSocket 中繼，背景升級 WebRTC；失敗就留在中繼。用公開 STUN，不架 TURN。
- 房主轉移：IndexedDB 恢復、後備複本、10 秒＋(k−1)×3 秒接手、epoch 防雙房主、手動交接。
- 不做「伺服器權威模式」。
- 單人離線：同一套房間邏輯在 Web Worker 執行，只換傳輸層。

## 影響與限制

- 房主持有全部隱藏資訊；這個設計適合朋友局，不適合公開競技。
- 中繼與連線安全的變更一律需要擁有者同意。

## 連線層獨立成通用函式庫（2026-11-27）

- 擁有者決定把連線層抽成 [mangreen/peerhost](https://github.com/mangreen/peerhost)（目前公開，之後再決定是否私有），
  讓本專案、king-of-tokyo 與之後的遊戲共用。
- 預定分工：peerhost 負責連線、中繼伺服器、房號、房主權威、重送與接回、房主轉移、大廳座位、聊天通道與測試工具；
  遊戲只提供規則介面（開局、套用動作、依玩家過濾畫面、驗證動作、電腦出招）。
- 預定時程：M2 定介面，M3–M5 分批移植，本遊戲是第一個使用者。
- 授權條款與本專案引用它的方式（版本固定方式）尚未決定。決定時另寫 ADR。
